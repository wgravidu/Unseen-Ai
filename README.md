# UNSEEN AI — Visual Wall Investigation

> See what's happening beneath the surface.

UNSEEN AI investigates visible wall damage from a photo. Upload or capture a wall
image, and Meta AI reports **only what it can see**, how confident it is, what it
**cannot** confirm, and — when the evidence is weak — **exactly which photo to
take next**. It never claims a definitive diagnosis.

What the demo shows:

1. A real peeling-wall photo is analyzed — confidence is only **45%**, so the AI
   asks for more evidence instead of guessing.
2. **Next Best View** tells the user the next photo to take (wide, ~2 m, straight
   angle) and marks the focus area on the photo.
3. **Damage Highlight** boxes the visible peeling area (0.90 visual certainty) —
   appearance only, never a cause.
4. A second photo plus a short answer is sent with the previous analysis —
   confidence rises to **62% (+17%)**, with a “What changed” summary.

## Features

- **Camera Scan** with a smart capture guide (too dark / blurry / too far / ready)
- **Gallery Upload** — up to 4 JPG/PNG/WebP photos (max 8 MB each), with a
  browser-side photo-quality gate before anything is sent
- **Meta AI Investigation** — `POST /analyze` (single photo) and
  `POST /investigate` (multi-round: photos + notes + previous analysis)
- **Next Best View** — the AI prescribes the next photo (focus box, distance,
  angle, priority)
- **Automatic Damage Highlight** — `POST /highlight` returns tight visible-region
  bounding boxes (0–1000 coordinates)
- **Interactive 3D Visualization** — the photo and mapped regions projected on a
  rotatable 3D wall panel
- **Two AI engines**
  - **API AI** — FastAPI backend → Meta AI (**Muse Spark**)
  - **Local AI** — runs entirely in the browser (Transformers.js + WebAssembly),
    offline; the photo never leaves the device. Experimental: measured pixel
    statistics, not trained wall-damage detection
- **PDF reports**, saved cases (IndexedDB), investigation history, and
  **English / Sinhala (සිංහල)** UI

## Architecture

```
Browser / Phone (React + Vite, HTTPS :5173)
      │  fetch(FormData)               └─ Local mode: analyzed in-browser, no upload
      ▼
FastAPI backend (HTTPS :8000)          backend/main.py
  GET  /health       server + API-key status
  POST /analyze      1 photo → observations, causes, confidence, Next Best View
  POST /investigate  photos + notes + previous analysis → updated analysis + "what changed"
  POST /highlight    1 photo → visible-damage bounding boxes
      │  OpenAI SDK — API key lives only in backend/.env, never in the browser
      ▼
Meta AI API (api.meta.ai/v1, model: muse-spark-1.3)
```

The frontend discovers the backend automatically (same hostname, port 8000),
so opening the app from a phone on the same Wi-Fi needs no configuration.

## Quick start

**Windows (easiest):** double-click [`start-app.bat`](start-app.bat) — it starts
the backend and frontend and opens the browser. For phone/camera use, open the
printed `https://<your-LAN-IP>:5173` address on the same Wi-Fi (HTTPS is required
for the camera; local certificates are generated by mkcert).

**Manual:**

```powershell
# Backend
cd backend
python -m pip install -r requirements.txt
# create backend/.env with MODEL_API_KEY (see backend code for MODEL_BASE_URL / MODEL_NAME)
python -m uvicorn main:app --host 0.0.0.0 --port 8000

# Frontend (new terminal)
cd unseen-ai
npm install
npm run dev
```

## Safety & honesty

- Outputs are **visual guidance only — not a professional inspection or a
  diagnosis**. Possible causes are labelled hypotheses with likelihoods, and
  every result carries this disclaimer.
- Highlight boxes and focus areas mark **visible appearance only**.
- The backend validates uploads (JPEG/PNG/WebP, ≤ 8 MB), normalizes and
  schema-validates the model’s JSON (Pydantic), and retries once on a malformed
  response. The frontend validates the payload shape again before rendering.
- CORS is restricted to local/LAN origins; the model API key is read only from
  the backend environment.
